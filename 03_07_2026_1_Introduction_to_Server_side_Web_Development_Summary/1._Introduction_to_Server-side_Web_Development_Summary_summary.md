## 1. 🌐 สถาปัตยกรรม Client-Server (Client-Server Architecture)

ระบบเว็บแอปพลิเคชันสมัยใหม่ทำงานอยู่บนรูปแบบ **Client-Server Model** ซึ่งเป็นการแบ่งบทบาทหน้าที่ระหว่างผู้ขอใช้บริการ (Client) และผู้ให้บริการ (Server):

```
┌──────────────────┐            HTTP Request             ┌──────────────────┐
│                  │────────────────────────────────────►│                  │
│  Client (Browser)│                                     │  Server (Backend)│
│  (Presentation)  │◄────────────────────────────────────│ (Business Logic) │
└──────────────────┘            HTTP Response            └──────────────────┘
```

1.  **Client (Front-end):** อุปกรณ์ฝั่งผู้ใช้งาน (เช่น Web Browser, Mobile App) ทำหน้าที่รับข้อมูล นำเสนอ UI/UX และส่ง **HTTP Request** ไปยัง Server
2.  **Server (Back-end):** เครื่องคอมพิวเตอร์เซิร์ฟเวอร์ ทำหน้าที่รับคำขอ ประมวลผลตรรกะทางธุรกิจ (Business Logic) ติดต่อฐานข้อมูล และส่ง **HTTP Response** กลับไปยัง Client

## 2. ⚔️ ความแตกต่างระหว่าง Frontend และ Backend

| มิติเปรียบเทียบ | Frontend (Client-Side) | Backend (Server-Side) |
| :--- | :--- | :--- |
| **หน้าที่หลัก** | การแสดงผลส่วนติดต่อผู้ใช้ (UI/UX), การตอบสนองผู้ใช้ | ตรรกะทางธุรกิจ (Business Logic), บริหารฐานข้อมูล, ความปลอดภัย |
| **เทคโนโลยีหลัก** | HTML5, CSS3, JavaScript (React, Vue, Angular) | Node.js, Python, Java, Go, Express.js, Databases |
| **การประมวลผล** | ทำงานบน Web Browser ของผู้ใช้แต่ละคน | ทำงานบน Cloud / Web Server ของผู้ให้บริการ |
| **ความปลอดภัย** | ซอร์สโค้ดถูกเปิดเผยต่อผู้ใช้ (Public View) | ซอร์สโค้ดและข้อมูลเป็นความลับ (Protected Environment) |

## 3. 🖥️ รูปแบบการแสดงผลเว็บไซต์ (Rendering Models)

```
[Server-Side Rendering (SSR)]   Server สร้าง HTML สมบูรณ์ ──► ส่งให้ Browser แสดงผลทันที
[Client-Side Rendering (CSR)]   Server ส่ง JS เปล่า       ──► Browser รัน JS สร้าง HTML เอง
```

### 3.1 Server-Side Rendering (SSR)
*   **การทำงาน:** Server ประมวลผลดึงข้อมูล ดึง HTML Template และประกอบร่างเป็นไฟล์ HTML สมบูรณ์ก่อนส่งกลับไปที่ Browser
*   **ข้อดี:** SEO ดีเยี่ยม (Search Engine อ่านเนื้อหาได้ทันที), หน้าแรกแสดงผลเร็ว (Fast Initial Load)
*   **ข้อเสีย:** Server ทำงานหนักขึ้นเมื่อมี Traffic สูง

### 3.2 Client-Side Rendering (CSR)
*   **การทำงาน:** Server ส่งไฟล์ HTML เปล่าพร้อมไฟล์ JavaScript ขนาดใหญ่ให้ Browser แล้ว Browser จะรัน JS เพื่อดึงข้อมูล API (JSON) มาสร้าง DOM บนหน้าจอเอง (เช่น Single Page Applications - SPAs)
*   **ข้อดี:** สลับหน้าเว็บรวดเร็วแบบไม่รู้สึกว่า Re-load (Smooth UX), ลดภาระของ Server
*   **ข้อเสีย:** SEO ทำได้ยากในอดีต, การโหลดครั้งแรกใช้เวลานาน (Slow Initial Load)

## 5. 💡 แนวคิดพื้นฐานที่ต้องรู้ในงาน Server-Side

1.  **Stateless Protocol:** โปรโตคอล HTTP ไม่มีการจดจำสถานะการร้องขอก่อนหน้า การระบุตัวตนผู้ใช้ในแต่ละ Request ต้องอาศัย **Sessions & Cookies** หรือ **Tokens (เช่น JWT - JSON Web Tokens)**
2.  **RESTful APIs (Representational State Transfer):** สถาปัตยกรรมสำหรับออกแบบ Web API โดยอิงตาม HTTP Methods:
    *   `GET` : ดึงข้อมูล (Read)
    *   `POST` : สร้างข้อมูลใหม่ (Create)
    *   `PUT` / `PATCH` : อัปเดตข้อมูล (Update)
    *   `DELETE` : ลบข้อมูล (Delete)
3.  **Security Essentials (ความปลอดภัยเบื้องต้น):**
    *   *Input Validation:* ตรวจสอบข้อมูลขาส่งเพื่อป้องกัน SQL Injection และ XSS (Cross-Site Scripting)
    *   *CORS (Cross-Origin Resource Sharing):* การกำหนดสิทธิ์ให้โดเมนอื่นเข้าถึง API
    *   *Authentication & Authorization:* การพิสูจน์ตัวตน (คุณคือใคร) vs การอนุมัติสิทธิ์ (คุณทำอะไรได้บ้าง)
